## Common Issues

### Content still jumping or flashing

If users still see wrong content that jumps when React loads:

<AccordionGroup>
  <Accordion title="Check if bind() is in useState initializer">
    The `bind()` function must be called inside a lazy `useState` initializer:

    ```tsx
    // Correct
    const [time, setTime] = useState(() => {
      const boundProps = bind('time');
      return boundProps.time || new Date();
    });

    // Wrong - bind() called outside useState
    const boundProps = bind('time');
    const [time, setTime] = useState(boundProps.time || new Date());
    ```
  </Accordion>

  <Accordion title="Check if key matches">
    The key passed to `bind()` must match what you expect in the returned object:

    ```tsx
    const [state, setState] = useState(() => {
      const boundProps = bind('state'); // Key is 'state'
      return boundProps.state;          // Access 'state' property
    });
    ```
  </Accordion>

  <Accordion title="Verify component is wrapped">
    Make sure your component is wrapped in `<Prehydrate>`:

    ```tsx
    // Correct
    <Prehydrate>
      <Clock bind={bind} />
    </Prehydrate>

    // Wrong - not wrapped
    <Clock bind={bind} />
    ```
  </Accordion>
</AccordionGroup>

### Content not updating before React loads

If the page still shows build-time values until React kicks in:

<AccordionGroup>
  <Accordion title="Check Content Security Policy">
    Some CSP configurations block inline scripts. Check your browser console for CSP errors.

    If using a strict CSP, you may need to add a nonce or adjust your policy:

    ```html
    <meta http-equiv="Content-Security-Policy"
          content="script-src 'self' 'unsafe-inline'">
    ```
  </Accordion>

  <Accordion title="Verify SSR is working">
    Prehydrate only generates scripts during server-side rendering. Check:

    1. View page source - you should see the inline `<script>` tag
    2. If no script, your page may not be using SSR
  </Accordion>

  <Accordion title="Check for JavaScript errors">
    Open browser DevTools and check for errors. Common issues:
    - Syntax errors in serialized functions
    - Missing dependencies
    - Invalid variable names
  </Accordion>
</AccordionGroup>

### Helper functions not working

If your formatting or calculation functions aren't doing anything:

<AccordionGroup>
  <Accordion title="Functions must be self-contained">
    Dependencies cannot reference external variables (closures):

    ```tsx
    // Wrong - references TAX_RATE from outer scope
    const TAX_RATE = 0.08;
    const addTax = (price) => price * (1 + TAX_RATE);
    deps: { addTax }

    // Correct - TAX_RATE is a parameter
    deps: {
      TAX_RATE: 0.08,
      addTax: (price, rate) => price * (1 + rate),
    }
    ```
  </Accordion>

  <Accordion title="Check function serialization">
    View page source and look at the generated script. Your function should appear as valid JavaScript:

    ```javascript
    // In generated script:
    const myFunction = function myFunction(x) { return x * 2; };
    ```

    If it looks wrong, the function may not serialize correctly.
  </Accordion>

  <Accordion title="Use valid identifier names">
    Dependency names must be valid JavaScript identifiers:

    ```tsx
    // Wrong
    deps: { 'format-time': formatTime }

    // Correct
    deps: { formatTime: formatTime }
    ```
  </Accordion>
</AccordionGroup>

### TypeScript Errors

<AccordionGroup>
  <Accordion title="Type 'unknown' errors">
    Use generics to specify your state type:

    ```tsx
    const { Prehydrate, bind } = prehydrate<Date>({
      key: 'clock',
      initialState: () => new Date(),
    });
    ```
  </Accordion>

  <Accordion title="bind() return type issues">
    Type your component props to match the expected return:

    ```tsx
    interface ClockProps {
      bind: (key: string) => Record<string, Date | undefined>;
    }

    function Clock({ bind }: ClockProps) {
      // ...
    }
    ```
  </Accordion>
</AccordionGroup>

## Debugging Tips

### See what Prehydrate is doing

The easiest way to understand what's happening is to view the generated code:

1. Open your page in the browser
2. View page source (Ctrl+U / Cmd+Option+U)
3. Search for `prehydrate-` to find the container
4. Look at the `<script>` tag that follows

### Add logging to see what's happening

During development, add some logs to trace the flow:

```tsx
// In your component
const [time, setTime] = useState(() => {
  const boundProps = bind('time');
  console.log('[Clock] bind returned:', boundProps);
  return boundProps.time || new Date();
});
```

### Know when prehydration finishes

```javascript
window.addEventListener('prehydration-complete', () => {
  console.log('Content is now showing the correct values');
});
```

## Framework-Specific Notes

### Next.js App Router

<Accordion title="Use 'use client' directive">
  Prehydrate components must be client components:

  ```tsx
  'use client';

  import { prehydrate } from 'prehydrate';
  // ...
  ```
</Accordion>

### Vite SSR

<Accordion title="Check entry files">
  Make sure you have separate entry points:

  - `entry-server.tsx` - uses `renderToString`
  - `entry-client.tsx` - uses `hydrateRoot`
</Accordion>
